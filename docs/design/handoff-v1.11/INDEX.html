A-t-on perdu des fonctions de ton app de base ?

Non — les 52 éléments inventoriés ont tous une place, et les 5 écrans du prototype les portent.

La preuve détaillée, élément par élément, est dans l'inventaire exhaustif (52 éléments, statut « conservé / fusionné / approfondi », aucun supprimé) et dans la matrice de couverture (33 fonctions de ton code, toutes recasées). Dans le prototype : salaire versable + réserve, santé, décisions suggérées, seuils micro & TVA avec leviers, calendrier mensuel fusionné avec congés, missions + occupation, factures + cycle URSSAF, clients + dépendance, charges, CA réalisé vs encaissé, trésorerie projetée + runway, provisions, IR barème vs libératoire (foyer + PER), CFE, rendement, rapprochement bancaire, CRA imprimable, et les 7 sections de Config avec exports CSV / FEC / JSON réels.

Les limites honnêtes du prototype

Tout est présent à l'écran et manipulable, mais c'est une maquette : les données sont fictives et certaines actions sont simulées (un toast confirme le geste sans le faire vraiment) :

  • Import bancaire — la zone de dépôt CSV/OFX est là, le parsing réel n'est pas branché.
  • Cloud sync — l'interface compte / appareils est là, sans vrai backend.
  • Envoi d'e-mails (relances, CRA) — le flux est montré, l'envoi est simulé.

Rien n'a été retiré : ces trois points sont des branchements techniques, pas des fonctions manquantes dans le design.
